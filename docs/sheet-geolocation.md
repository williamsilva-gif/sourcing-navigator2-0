## Real integration and safe execution
Shared server-only Google transport extracted unchanged from proximity functions. Same existing server key / explicit gateway mode, no credentials exposed in the browser. Geocoding for unnamed offices/stores never invents establishment identity. Hotels with uncertain geocoding use Places API (New) unique candidate search + Details, validating ID and physical address; ambiguity stays review. City/UF/CEP/number, partial results and precision are validated, interpolated/approximate coordinates remain review. Places identity confidence is not labeled ROOFTOP.

Server requests handle at most three rows sequentially, persist each row outcome/history/checkpoint, reserve each outbound call before network I/O, enforce a per-file user-approved request cap (default 2,000, maximum 6,000), throttle between lookups and between chunks, and use a tenant-wide advisory lease to prevent concurrent chunks across these jobs. 429/5xx/timeouts retry with persisted exponential delay, maximum three attempts. Authentication/configuration errors pause with explicit messages. If interrupted, the lease expires in 180 seconds and processing can resume; reserved calls may exceed actual calls after a crash, but never exceed the approved cap. External API calls cannot be transactionally exactly-once during a crash; saved responses deduplicate identical addresses/identities in the same file.

No scheduler or automatic run on upload/reopen: user must check cost authorization and click **Iniciar / retomar Google**. Closing the tab stops new requests; in-flight bounded request can finish. Pause/cancel prevent new provider calls; completed attempts are labeled processed, not 100% verified. High-confidence count is distinct from checkpoint and review/error counts. Partial exports remain available even if the cap is reached. Increase/reconfigure budgets and manual result overrides are not exposed in this version; review rows are exported for audit rather than silently approved.

## Verification
### New blank-coordinate reprocessing — 2026-11-09 (preview only)
New parsed rows carry localizationVersion 2; historical rows/jobs are not rewritten or reprocessed. New unit candidates are scored with hard finite-coordinate/BR/UF/city gates, explicit number and normalized street agreement ahead of postal support. A uniquely superior ROOFTOP numbered address can be high despite divergent source CEP (observed separately); plausible ambiguity and street-only coordinates are retained as review, never definitive. Hotels retain stricter CEP/Places identity rules. Selection is deterministic and does not call the provider.

Only explicit start calls the existing server transport. New offices/stores stop at a plausible geocode; otherwise try address without CEP, named POI through `/places/v1/places:searchText` (no lodging restriction), then matching CEP/city/UF as a review-only postal centroid. At most four calls per attempt (initial plus three fallbacks), each reserved against the existing cap/lease before network I/O. No municipal centroid substitute is implemented: no real compatible result means an explicit no-location error, not fabricated coordinates. POI latitude/longitude refer to the named physical landmark, not its surrounding city or proof of a numbered unit.

CSV decoding preserves UTF-8 accents (Windows-1252 fallback), leading-zero codes and original columns; original address and original CEP aliases map automatically, original CEP takes precedence when both postal columns exist and the user can choose either. Slash/comma/Nº explicit numbers are extracted only for queries. Each job has one chosen category. Excel fills only empty non-formula original Latitude/Longitude cells of version-2 rows and labels appended coordinates Latitude Google/Longitude Google when the original headers exist; nonempty source coordinates remain untouched. Originals in private storage remain immutable.

Mocked tests cover numbered-address scoring with divergent CEP, retained ambiguous coordinates, airport POI, wrong geography/invalid coordinates, review-only postal centroids, query-only number extraction, lossless CSV enrichment, historical snapshot behavior, cap/fatal errors, retries and reload/completion. Live Google rendering/API behavior remains unverified by design; validate only after your own upload and explicit start on an authorized origin.
