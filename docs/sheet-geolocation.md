## Real integration and safe execution
Shared server-only Google transport extracted unchanged from proximity functions. Same existing server key / explicit gateway mode, no credentials exposed in the browser. Geocoding for unnamed offices/stores never invents establishment identity. Hotels with uncertain geocoding use Places API (New) unique candidate search + Details, validating ID and physical address; ambiguity stays review. City/UF/CEP/number, partial results and precision are validated, interpolated/approximate coordinates remain review. Places identity confidence is not labeled ROOFTOP.

Server requests handle at most three rows sequentially, persist each row outcome/history/checkpoint, reserve each outbound call before network I/O, enforce a per-file user-approved request cap (default 2,000, maximum 6,000), throttle between lookups and between chunks, and use a tenant-wide advisory lease to prevent concurrent chunks across these jobs. 429/5xx/timeouts retry with persisted exponential delay, maximum three attempts. Authentication/configuration errors pause with explicit messages. If interrupted, the lease expires in 180 seconds and processing can resume; reserved calls may exceed actual calls after a crash, but never exceed the approved cap. External API calls cannot be transactionally exactly-once during a crash; saved responses deduplicate identical addresses/identities in the same file.

No scheduler or automatic run on upload/reopen: user must check cost authorization and click **Iniciar / retomar Google**. Closing the tab stops new requests; in-flight bounded request can finish. Pause/cancel prevent new provider calls; completed attempts are labeled processed, not 100% verified. High-confidence count is distinct from checkpoint and review/error counts. Partial exports remain available even if the cap is reached. Increase/reconfigure budgets and manual result overrides are not exposed in this version; review rows are exported for audit rather than silently approved.
