# Architecture rules
- Ten-kilometer crossing uses isolated pure calculation/export and TA tenant-scoped read-only sheet-job endpoints, with mapped browser-only full-source imports replacing (never merging) jobs and temporary supplements; never import geocoding batches or legacy radius state, so calculation cannot incur Google costs or mutate originals.
- Independent spreadsheet geolocation owns tenant-scoped TA jobs, private immutable originals and per-row checkpoints; shared server-only Google transport preserves existing callers while explicit-start batches never write radius jobs or hotel catalog.
- Sheet-specific Places validation wraps the legacy validator; exceptions never change radius validation or promote historical rows without complete retained provider evidence.
- Sheet batches isolate row failures with bounded persisted retries; lease-guarded completion and paused snapshot normalization never call Google, preserving costs and prior outcomes.
- Version new sheet rows to isolate unit scoring and bounded POI/postal fallbacks from historical processing; pure selection never creates coordinates, and enrichment fills only requested empty coordinates while retaining separate Google provenance.
- Raio & Proximidade owns its libraries, client-only TA gate, tenant-scoped jobs and private originals; bounded authenticated requests advance durable address checkpoints and lease state without touching existing RFPs. This isolates confidential sourcing and makes interrupted work resumable.
- Proximity establishment fallback uses server-only Places API (New), unique candidate validation and separate derived address provenance; identity-aware checkpoints prevent copying one property's confirmation to another.
- Proximity reads hotel catalog through authenticated selective queries and stores match audits only in its jobs; independent bundled GeoNames municipal references screen coordinate outliers without paid lookups or modifying catalog rows.
- Tax Impact Check lives in its own library/components and protected named route; reuse existing app shell without changing other modules.
- Original spreadsheets use a dedicated private bucket, while immutable imports and comparison revisions reference tenant-scoped analyses; this preserves provenance and reproducibility.
- Parse spreadsheets and compute comparisons again in authenticated server functions with the caller's RLS client; client previews are not authoritative.
- Use an isolated client-only pathless auth layout for Tax Impact Check because the existing authenticated layout redirects during SSR; do not change existing routes to resolve that legacy behavior.
- Keep tax hypotheses, historical-volume parsing and report generation in isolated Tax Impact libraries; simulation settings are analysis-scoped and do not mutate immutable comparison revisions.
- Daily official-source checks use tenant-scoped database leases and fixed outbound URLs; only the authorized server may write verification-cache statuses to prevent browser forgery, and an unconfirmed Senate resolution never changes the rule automatically.- Proximity Routes DRIVE/WALK are pure-parsed in src/lib/proximity/routes.ts and stored as additive pair fields beside legacy roadKm; calls are explicit, capped (top 3 same-city per category or one pair) and never re-bill calculated routes.
